## ১. প্রজেক্টের পরিচিতি

### ১.১ সমস্যা কী ছিল (SRS §4)

বাংলাদেশের ছোট অনলাইন বিক্রেতারা ব্যবসা চালায় ফেসবুক/ইনস্টাগ্রাম মেসেজ, এক্সেল শিট, খাতা, ফোনকল আর কুরিয়ার কোম্পানির ড্যাশবোর্ড মিলিয়ে। ফলে:

- ডাটা ছড়িয়ে-ছিটিয়ে থাকে — এক জায়গা থেকে পুরো ব্যবসার ছবি দেখা যায় না
- অর্ডার, ইনভেন্টরি, পেমেন্ট সব হাতে লিখতে হয়
- সাধারণ টুল শুধু বলে "কী হয়েছে", "কেন হয়েছে" বলে না
- কত স্টক কিনবেন সেটাও আন্দাজের উপর থাকে
- ক্যাশ অন ডেলিভারিতে (COD) ক্যান্সেল আর রিটার্ন লাভ খেয়ে ফেলে

## ৩. সিস্টেম আর্কিটেকচার

### ৩.১ তিন-সার্ভিস কাঠামো (SRS §26)

```
+---------------------------------------------------------------+
|  FRONTEND - React 18 + Vite + Tailwind + Recharts            |
|  http://localhost:5173                                        |
+-------------------------------+-------------------------------+
                                | REST/JSON + JWT bearer token
+-------------------------------v-------------------------------+
|  BACKEND  - Node.js + Express                                |
|  http://localhost:5000/api                                    |
|  routes -> auth/RBAC middleware -> controllers -> services    |
+----------------+------------------------------+----------------+
                 | Sequelize ORM                | HTTP POST (data bundle)
+----------------v---------------+  +----------v-------------------+
|  DATA - PostgreSQL/SQLite    |  |  AI SERVICE - Python FastAPI |
|  17 tables                   |  |  http://localhost:8001        |
+--------------------------------+  |  XGBoost + sklearn + pandas  |
                                    +-------------------------------+
```

### ৩.২ AI অংশ আলাদা সার্ভিস কেন (মাইক্রোসার্ভিস)

1. SRS-ই বলেছে (§2.1, §26) Python AI/ML সার্ভিস আলাদা লেয়ার হবে
2. XGBoost/pandas শুধু Python-এ পাওয়া যায়, বাকি অ্যাপ JS-এ — আলাদা প্রসেস ছাড়া উপায় নেই
3. ML কোড আলাদাভাবে ট্রেইন/ডিপ্লয় করা যায়, ব্যবসার API অক্ষত থাকে (NFR-06)
4. AI সার্ভিস বন্ধ থাকলেও ব্যাকএন্ড পরিষ্কার 503 এরর দেয় — অর্ডার, ইনভেন্টরি, পেমেন্ট সব **চলতেই থাকে**

### ৩.৩ "ডাটা বান্ডল" প্যাটার্ন — ব্যাকএন্ড ও AI-এর কথোপকথন

AI সার্ভিস সরাসরি ডাটাবেজে ঢোকে না। বরং ব্যাকএন্ড ব্যবসার **পুরো স্ন্যাপশট** JSON বানিয়ে প্রতি AI রিকোয়েস্টের সাথে পাঠায়: সব অর্ডার (আইটেম, পেমেন্ট, রিটার্নসহ), প্রোডাক্ট+স্টক, কাস্টমার, মাসিক/দৈনিক সিরিজ, প্রফিট মেট্রিক্স।

কেন এভাবে: অথরাইজেশন এক জায়গায় থাকে (29.4), Python-এ দ্বিতীয়বার ORM লিখতে হয় না, AI সার্ভিস stateless থাকে, টেস্ট করা সহজ, আর প্রতিটা AI ফলাফল AIPredictions টেবিলে **লগ হয়** — কখন কী বলেছিল পরে দেখা যায়।

### ৩.৪ মডেল ক্যাশিং (BR-06)

১,৬০০+ অর্ডারে XGBoost ট্রেইনিং কয়েক সেকেন্ড লাগে — প্রতি রিকোয়েস্টে ট্রেইন করলে UI ধীর হয়ে যেত। তাই AI সার্ভিস প্রতি ব্যবসার জন্য মেমরিতে মডেল ক্যাশ রাখে, যার চাবি: (ক) ডাটার ফিঙ্গারপ্রিন্ট — ডাটা বদলালে আবার ট্রেইন, (খ) ১০ মিনিটের TTL।

### ৩.৫ যথেষ্ট ডাটা না থাকলে AI চুপ থাকে (BR-06, BR-07)

## ৪. ডাটাবেজ ডিজাইন — ১৭টি টেবিল (SRS §28)

```
Business --+- Users                    (owner/manager/staff)
                    +- Categories - Products - Inventory - InventoryTransactions
                    +- Customers - Orders - OrderItems
                    |                +- Payments   (COD payment)
                    |                +- ReturnRecords (returns)
                    |                +- Cancellations (cancel reasons)
                    |                +- Deliveries   (courier/tracking)
                    +- Expenses - AIPredictions - AIRecommendations - Notifications
```

গুরুত্বপূর্ণ টেবিল আর তাদের বিশেষত্ব:

| টেবিল | কাজ | বিশেষ সিদ্ধান্ত |
|---|---|---|
| Products | ক্যাটালগ | isActive=false মানে **সফট ডিলিট** (FR-07) — পুরনো অর্ডারের ইতিহাস বাঁচা থাকে |
| Inventory | বর্তমান স্টক | currentStock-এ min:0 ভ্যালিডেশন — ডাটাবেজ স্তরেই নেগেটিভ স্টক অসম্ভব (BR-02) |
| InventoryTransactions | স্টকের পুরো খতিয়ান (FR-10) | প্রতিটা মুভমেন্টের signed quantity + balanceAfter + কোন অর্ডার/রিটার্নের রেফারেন্স |
| Orders | মূল টেবিল | ৮টি স্টেটাস, অর্ডার নম্বর BM-2026-00001, placedVia (facebook/instagram/...), riskScore (AI-এর ক্যাশ করা স্কোর) |
| OrderItems | লাইন আইটেম | unitPrice ও **unitCost স্ন্যাপশট** — দাম বদলালেও পুরনো অর্ডারের প্রফিট বদলায় না |
| Payments | টাকার হিসাব (FR-16/17) | COD-এর জন্য: collectedAmount, courierCharge, returnCharge |
| ReturnRecords | রিটার্ন (FR-18) | condition: resellable হলে স্টকে ফেরে, damaged হলে ফেরে না (BR-05) |
| Cancellations | ক্যান্সেলের কারণ (FR-19) | SRS-এর ৬টি কারণ + কোন স্টেজে ক্যান্সেল হলো |

**কেন Sales নামে টেবিল নেই?** SRS একে এন্টিটি হিসেবে লিস্ট করলেও আমরা সেলস সংখ্যা **হিসাব করে বের করি** delivered অর্ডার থেকে। আলাদা Sales টেবিল মানে দ্বিতীয় সত্যের উৎস — স্টেটাস বদলালে দুই জায়গায় আপডেট করতে হতো, এক জায়গা মিস হলেই অ্যানালিটিক্স নষ্ট। রিয়েল-টাইম হিসাব সবসময় সঠিক থাকে।

**মাল্টি-টেন্যান্সি (29.4):** প্রতিটা টেবিলে businessId আছে; প্রতিটা কোয়েরি লগইন-করা ইউজারের ব্যবসা দিয়ে ফিল্টার হয়। অন্য ব্যবসার কোনো রো-এর ID আন্দাজে দিলেও পাওয়া যায় না (404)।

**PostgreSQL/SQLite সুইচ:** backend/.env-এ DB_DIALECT=postgres বা sqlite লাইনটা বদলালেই হয়; দুই কনফিগই রাখা আছে (.env, .env.sqlite-backup, .env.example)।

### ৫.২ services/orderService.js — অর্ডারের ব্রেইন (FR-13/14/15)

- **createOrder:** টাকার হিসাব সার্ভারেই হয় — ক্লায়েন্ট শুধু productId আর quantity পাঠায়, দাম ক্যাটালগ থেকে নেওয়া হয়। ক্লায়েন্ট প্রতারণা করে দাম বদলাতে পারে না। অর্ডার+আইটেম+পেমেন্ট এক ট্রানজেকশনে তৈরি হয়।

- **স্টক কাটে কখন?** confirm হলে (pending-এ নয়) — কারণ ফোনে কনফার্মেশনের আগে পending অর্ডার অনেক বেশি থাকে। ক্যান্সেল করলে কাটা স্টক **ফেরত আসে**।
- **recordReturn (BR-05):** ফেরত নেওয়ার পরিমাণ কেনা পরিমাণের বেশি হতে পারে না (একাধিক রিটার্ন মিলিয়ে হিসাব); resellable হলে স্টকে ফেরে, damaged হলে প্রফিটে ক্ষতি হিসাব হয়। পুরো অর্ডার ফেরত গেলে স্টেটাস returned + রিফান্ড।
- **searchOrders (FR-15):** অর্ডার নম্বর, কাস্টমার নাম/ফোন, তারিখ, স্টেটাস, প্রোডাক্ট — সব দিয়ে খোঁজা যায়।

## ৬. AI/ML সার্ভিস — ভেতরের গল্প

### ৬.১ core/features.py — ফিচার ইঞ্জিনিয়ারিং

- অর্ডার থেকে ফ্ল্যাগ: is_cod, high_value (৳২,৫০০+), is_dhaka, cancelled, returned
- ক্যালেন্ডার ফিচারে **is_bd_weekend** (শুক্র/শনি — বাংলাদেশের শপিং-পিক; পশ্চিমা মডেল শনি/রবি ধরে)
- টাইম-সিরিজ ফিচার: lag 1/2/3/7/14/30, রোলিং মিন/স্ট্ড
- **লিক-ফ্রি কাস্টমার হিস্ট্রি:** প্রতিটা অর্ডারের কাস্টমার-স্ট্যাট (আগের ক্যান্সেল রেট, রিটার্ন রেট, অর্ডার সংখ্যা) শুধু **আগের** অর্ডার থেকে হিসাব হয় (expanding window, shifted) — মডেল যেন উত্তরপত্র দেখে পরীক্ষা না দেয় (target leakage প্রতিরোধ)।

### ৬.২ তিনটি মডেল (core/models.py)

**SalesForecaster (FR-24):** দৈনিক ইউনিটের উপর XGBoost + Ridge ব্লেন্ড (GBM স্পাইক/সিজন ধরে, Ridge লেভেল স্থিতিশীল রাখে)। রিকার্সিভভাবে ৭/৩০/৯০ দিন ভবিষ্যৎ বলে; কনফিডেন্স ব্যান্ড সময়ের সাথে **চওড়া হয়** — অনিশ্চয়তা লুকানো হয় না।

**DemandModel (FR-25):** সব প্রোডাক্ট মিলিয়ে এক XGBoost রিগ্রেসর (প্রোডাক্ট-আইডেন্টিটি ফিচার) — আলাদা ১৮টা ছোট মডেলের চেয়ে ডাটা বেশি পায়। ৩০ দিনের চাহিদা + ট্রেন্ড লেবেল।

**RiskModel (FR-26):** দুটি ক্লাসিফায়ার — ক্যান্সেল আর রিটার্ন। ১২টি ফিচার: COD কি না, অর্ডারের মূল্য, আইটেম সংখ্যা, ঢাকা কি না, কাস্টমারের আগের ক্যান্সেল/রিটার্ন রেট, ইত্যাদি। ওপেন অর্ডারগুলোকে স্কোর করে (HIGH ৬০%+, MEDIUM ৩৫%+)। যে প্যাটার্নটা শেখে: **দামি COD অর্ডার + আগে ক্যান্সেল করা কাস্টমার = বিপদ** — UI তখন বলে "পাঠানোর আগে ফোন দিন"।

### ৬.৩ core/recommender.py — FR-27 ও FR-28

**ইনভেন্টরি রিকমেন্ডেশন:** cover_days = লিড টাইম + সেফটি ডেজ; target = প্রতিদিনের প্রেডিক্টেড চাহিদা x cover + reorder level; কেনার পরিমাণ = target - বর্তমান স্টক। ML ডাটা কম হলে velocity-ভিত্তিক ফলব্যাক (উত্তরে method: ml/velocity লেখা থাকে — স্বচ্ছতা)।

**অটো ইনসাইট (৬টি ডিটেক্টর):** সেলস-বনাম-প্রফিট অসামঞ্জস্য (SRS-এর ফ্ল্যাগশিপ উদাহরণ), রিটার্ন রেট বাড়ছে, ক্যান্সেল বাড়ছে, COD-নির্ভরতা, ডিসকাউন্ট-চাপ, ৩-মাসের গ্রোথ ট্রেন্ড। মাস-টু-ডেট তুলনা করা হয় **দৈনিক গড়ে** ভাগ করে — ৭ দিন বনাম পুরো মাসের অন্যায় তুলনা এড়াতে।

### ৬.৪ core/assistant.py — কেন ChatGPT নয়? (FR-29)

উত্তরগুলো (ক) এই ব্যবসার **আসল সংখ্যা** দিয়ে গঠিত হতে হবে, (খ) ভাইভার সময় **ইন্টারনেট/API key ছাড়া** চলতে হবে, (গ) **নির্ধারিত ও পরীক্ষাযোগ্য** হতে হবে। তাই ১১টি intent-এর কীওয়ার্ড-ম্যাচার + টেমপ্লেট, যা লাইভ হিসাব দিয়ে ভরা হয়। SRS-এর চারটি উদাহরণ-প্রশ্নের সবগুলোর উত্তর দেয়, সাথে থাকে follow-up চিপ আর BR-07 disclaimer।

- পাসওয়ার্ড bcrypt দিয়ে হ্যাশ (টেস্টে প্রমাণিত: প্লেইন টেক্সট কোথাও থাকে না)

- রোল-পারমিশন ম্যাট্রিক্স প্রতিটা রাউটে + ফাইন্যান্স গার্ড
- প্রতিটা কোয়েরি businessId-স্কোপড (29.4)
- ইনপুট ভ্যালিডেশন: express-validator + Sequelize মডেল ভ্যালিডেশন (29.5)
- auth এন্ডপয়েন্টে রেট লিমিট, helmet হেডার (29.6)
- প্রতিটা API উত্তরে passwordHash কখনো যায় না (toPublicJSON)

## ১০. টেস্টিং (SRS §35) — মোট ৪৬টি, সব পাস

**ব্যাকএন্ড (Jest, ২৫টি):** FR-22 ফর্মুলার ৫টি টেস্ট; BR-01 ট্রানজিশনের ৬টি; ইন্টিগ্রেশন ১৪টি — রেজিস্ট্রেশন+হ্যাশিং, BR-04 দুই দিক থেকে, BR-02 oversell, পুরো হ্যাপি-পাথ (তৈরি -> কনফার্মে স্টক কাটা -> ক্যান্সেলে ফেরত)।

**AI সার্ভিস (pytest, ২১টি):** ফিচার ইঞ্জিনিয়ারিং, ফোরকাস্টের বাউন্ড (নিম্ন অনুমান মূল অনুমানের মধ্যে, ঋণাত্মক নয়), রিস্ক রেঞ্জ, রিকমেন্ডার, ছয় intent, API চুক্তি।

**একটি সত্য ঘটনা (শিক্ষণীয়):** টেস্টগুলো আগে শুধু আলাদা SQLite ফাইল ঠিক করত; প্রজেক্ট PostgreSQL-এ গেলে `npm test` ভুল করে **আসল ডাটাবেজ মুছে ফেলেছিল** (sync force:true)। ঠিক করা হয়েছে — টেস্ট এখন কোডেই DB_DIALECT=sqlite বলে দেয়, PostgreSQL কখনো টাচ হয় না।

## ১১. ডেমো ডাটার ডিজাইন — ডেমো যেন জীবন্ত লাগে

"GhorerBazaar BD" নামের একটা ঢাকার অনলাইন ফ্যাশন ব্যবসা: নির্দিষ্ট-সিড PRNG (প্রতিবার একই ফল), ১০ মাসে ১,৬৫০+ অর্ডার — মাসভিত্তিক গ্রোথ (০.৫৫x থেকে ১.৩৫x), শুক্র/শনিবারের চূড়া, দুটি উৎসব-স্পাইক, ৭৮% COD, প্রোডাক্টভেদে রিটার্ন রেট (জুতা ১৯%, অ্যাকসেসরিজ ৫%), ~২০% কাস্টমার "ঝুঁকিপূর্ণ" (রিস্ক মডেলের জন্য শেখার উপাদান)। শেষ ৫ দিনে ওপেন অর্ডার (রিস্ক স্কোরিং ডেমোর জন্য), আর দুটি প্রোডাক্ট ইচ্ছা করে প্রায় শূন্য স্টকে (লো-স্টক অ্যালার্ট + "এখনই কিনুন" রিকমেন্ডেশন দেখাতে)।

## ১২. চালাবো যেভাবে

**এক-ক্লিক:** start.bat ডাবল-ক্লিক (বা VS Code টার্মিনালে `.\start.bat`) — ৩টি উইন্ডো + ব্রাউজার (http://localhost:5173)। বন্ধ করতে stop.bat।

**ম্যানুয়াল (৩ টার্মিনাল):**

```
cd ai-service && python -m uvicorn app.main:app --port 8001   (AI)
cd backend   && npm run dev                                     (API)
cd frontend  && npm run dev                                     (Web)
```

**নতুন পিসিতে প্রথমবার:** Node.js 18+ ও Python 3.10+ ইনস্টল -> backend ও frontend-এ `npm install`, ai-service-এ `pip install -r requirements.txt`, তারপর backend-এ `npm run seed`। পুরো চেকলিস্ট SETUP-FOR-TEAM.txt-তে।

**ডাটাবেজ:** zip-এ SQLite (কিছু সেটআপ লাগে না); প্রোডাকশন/ডেভ মেশিনে PostgreSQL (bizmind ডাটাবেজ, .env-এ কনফিগ, `npm run seed`)।

## ১৫. সীমাবদ্ধতা ও ভবিষ্যৎ

**সীমাবদ্ধতা (SRS §37):** প্রেডিকশনের মান ডাটার পরিমাণ/গুণমানের উপর নির্ভরশীল; ফলাফল অনুমান কখনোই গ্যারান্টি নয় (BR-07); কুরিয়ার/ফেসবুক/পেমেন্ট-গেটওয়ে লাইভ ইন্টিগ্রেশন এখনো নেই (কিন্তু placedVia, courier, tracking ফিল্ড ভবিষ্যতের হুক হিসেবে রাখা); প্রফেশনাল অ্যাকাউন্টিংয়ের চেয়ে সরল আর্থিক হিসাব; একাডেমিক স্কোপে sequelize.sync (মাইগ্রেশন নয়)।

**ভবিষ্যৎ (SRS §38):** ফেসবুক/ইনস্টাগ্রাম থেকে অর্ডার ইমপোর্ট, কুরিয়ার API ট্র্যাকিং, পেমেন্ট গেটওয়ে, আরও ভালো টাইম-সিরিজ মডেল, **বাংলা AI অ্যাসিস্ট্যান্ট**, মাল্টি-বিজনেস এজেন্সি মোড, Docker ওান-কমান্ড ডিপ্লয়।
